Character Set Options

The Oracle protocol module tells clients which character sets to expect, by Oracle character set id. It doesn't convert any data, so these options should match what the back-end database actually sends.

The charset option sets the database character set. It defaults to 873 (AL32UTF8) at every Server Version. If the back-end connection's nls_lang is a single byte character set, set charset to match (eg. 31 for WE8ISO8859P1).

The nationalcharset option sets the national character set. It defaults to 2000 (AL16UTF16), and rarely needs to be changed.

If a client can't decode a result set, try setting charset to 178 (WE8MSWIN1252), which decodes any byte, though not always to the right character.

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="oracle">
		<listeners>
			<listener protocol="oracle" port="1521" charset="178" nationalcharset="2000"/>
		</listeners>
		<connections>
			<connection string="user=scott;password=tiger;oracle_home=/u01/app/oracle/product/12.1.0;oracle_sid=ora1"/>
		</connections>
	</instance>
</instances>

Any Oracle character set id may be used. 0, or anything that isn't a number, is the same as leaving the option out. To look up the ids of a database's own character sets, run:

select parameter,value,nls_charset_id(value)
from nls_database_parameters
where parameter in ('NLS_CHARACTERSET','NLS_NCHAR_CHARACTERSET');
