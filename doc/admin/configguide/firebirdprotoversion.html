Protocol Version

When a Firebird client connects, it offers a list of the protocol versions it can speak, and the server picks one. Each version adds features, so client and server have to agree on which ones are in use.

The Firebird protocol module speaks version 10, and versions 11 and up to a maximum, which defaults to 13. Version 13 brought the plugin-based login (Srp, Srp256 and Legacy_Auth) and the packed message format that current clients use, and it is the highest version that has been proven against a real client.

The maxprotocolversion attribute on the listener tag changes the maximum. It accepts a plain decimal integer from 1 to 20. Leaving it out, setting it to 0, or setting it to anything above 20 is the same as the default of 13. Version 10 is the oldest the module speaks, and is always accepted, so any value from 1 to 10 limits the module to version 10.

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="firebird">
		<listeners>
			<listener protocol="firebird" port="3050" maxprotocolversion="12"/>
		</listeners>
		<connections>
			<connection string="user=firebirduser;password=firebirdpassword;db=firebirdhost:/opt/firebird/firebirddb.gdb"/>
		</connections>
	</instance>
</instances>

Raising the maximum above 13 is opt-in. Versions 14 through 20 add op_ping, batch operations, op_repl_data, statement timeouts, scrollable cursors (op_fetch_scroll and op_info_cursor), and prepare flags, none of which have been run against a real client yet. Some of those operations - op_ping and the scrollable cursor operations among them - aren't implemented at all, so a client that negotiates a higher version and then uses one of them has its session ended. See Limitations.

Lowering the maximum below 13 turns off the plugin-based login. Clients log in with the older password hash instead, and wire encryption is unavailable, since only version 13 and up has anywhere to carry the encryption key. See Wire Encryption.
