Client Protocol Flags

Separately from the handshake packet version, the handshake also advertises a set of capability flags that tell the client what the server can do. Two of those flags - CLIENT_PROTOCOL_41 (the 4.1-and-later wire format) and CLIENT_PLUGIN_AUTH (pluggable authentication methods) - are controlled by the clientprotocol attribute on the listener tag.

Setting clientprotocol to "41" (the default) advertises both flags, which is what every currently supported MySQL/MariaDB client expects. Setting it to any other explicit value clears both flags, for a client too old to speak the 4.1 protocol at all. Leaving it unset, or setting it to 0 or to something that isn't a number, is the same as setting it to 41.

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="mysql">
		<listeners>
			<listener protocol="mysql" port="3306" clientprotocol="9"/>
		</listeners>
		<connections>
			<connection string="user=mysqluser;password=mysqlpassword;db=mysqldb;host=mysqlhost"/>
		</connections>
	</instance>
</instances>

As with handshake, there is normally no reason to set this. It exists only for a client old enough to predate the 4.1 protocol. It has no effect when handshake is also set to send the legacy protocol 9 packet, which carries no capability flags at all.
