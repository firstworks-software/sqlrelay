Primary-Replica Query Routing

The load balancing scenarios described on previous pages all assume that multi-primary replication is being used. SQL Relay supports primary-replica replication as well.

In a primary-replica replication environment, SQL Relay can be configured to route DML and DDL queries to the primary and distribute selects over the replicas.

This actually requires 3 instances of SQL Relay. One to connect to the primary, one to connect to the replicas, and a third to route queries to the first two.

<?xml version="1.0"?>
<instances>

        <!-- This instance maintains connections to the "primary" MySQL database
                on the primarydb machine.  This instance only listens on the
                unix socket /tmp/primary.socket and thus cannot be connected to
                by clients from another machine. -->
        <instance id="primary" socket="/tmp/primary.socket" dbase="mysql">
                <connections>
                        <connection string="user=primaryuser;password=primarypassword;host=primarydb;db=primary;"/>
                </connections>
        </instance>


        <!-- This instance maintains connections to 4 "replica" MySQL databases
                on 4 replica machines.  This instance only listens on the unix
                socket /tmp/replica.socket and thus cannot be connected to by
                clients from another machine. -->
        <instance id="replica" socket="/tmp/replica.socket" dbase="mysql">
                <connections>
                        <connection string="user=replicauser;password=replicapassword;host=replicadb1;db=replica;"/>
                        <connection string="user=replicauser;password=replicapassword;host=replicadb2;db=replica;"/>
                        <connection string="user=replicauser;password=replicapassword;host=replicadb3;db=replica;"/>
                        <connection string="user=replicauser;password=replicapassword;host=replicadb4;db=replica;"/>
                </connections>
        </instance>


        <!-- This instance sends DML (insert,update,delete) and
                DDL (create/delete) queries to the "primary" SQL Relay instance
                which, in turn, sends them to the "primary" database.
                This instance sends any other queries to the "replica" SQL Relay
                instance which, in turn, distributes them over the "replica"
                databases. -->
        <instance id="router" dbase="router">
		<auths>
			<auth module="sqlrclient_userlist">
                        	<user user="routeruser" password="routerpassword"/>
			</auth>
		</auths>
		<routers>
                        <!-- send all DML/DDL queries to "primary"  -->
			<router module="regex" connectionid="primary">
				<pattern pattern="^drop "/>
				<pattern pattern="^create "/>
				<pattern pattern="^insert "/>
				<pattern pattern="^update "/>
				<pattern pattern="^delete "/>
			</router>
                        <!-- send all other queries to "replica" -->
			<router module="regex" connectionid="replica">
				<pattern pattern=".*"/>
			</router>
		</routers>
		<connections>
			<connection connectionid="primary" string="socket=/tmp/primary.socket;user=primaryuser;password=primarypassword"/>
			<connection connectionid="replica" string="socket=/tmp/replica.socket;user=replicauser;password=replicapassword"/>
		</connections>
        </instance>

</instances>

The first two instances use familiar configuration options, but the third uses a dbtype of "router" and uses router tags to define query routing rules.

(Note the module attribute of the router tag. SQL Relay is highly modular, and many advanced features, including query routing, are implemented by loadable modules.)

(Note also the use of a notifications tag. See Notifications for more information.)

Each router tag defines a connectionid to send the query to and a set of regular expression patterns to match. Queries that match the set of patterns defined in the pattern tags are sent to the instance of SQL Relay designated by the connectionid in the router tag.

The three instances can be started using:

sqlr-start -id primary
sqlr-start -id replica
sqlr-start -id router
( NOTE: When installed from packages, SQL Relay may have to be started and stopped as root.)

Client applications should connect to the router instance rather than the primary or replica instances.

sqlrsh -host sqlrserver -user routeruser -password routerpassword
