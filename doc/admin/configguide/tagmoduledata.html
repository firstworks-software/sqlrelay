tag

The tag moduledata module stores an arbitrary set of tags against the query currently running on a cursor. It doesn't tag anything itself - it's a place for other modules to store and look up tags. Typically a tag filter instance writes the tags, and a translation, router, or logger module reads them back later in that same query's lifecycle.

An example configuration follows.

<?xml version="1.0"?>
<instances>
	<instance ...>
		...
		<moduledatas>
			<moduledata module="tag" id="tags"/>
		</moduledatas>
		...
	</instance>
</instances>

Besides the module attribute (which must be set to "tag"), the tag moduledata module takes only the id attribute that all moduledata instances take:

  • id - Required. Identifies this instance of the moduledata module so that other modules can reference it. Filter, translation, router, and logger modules that read or write tags do so by referencing this id, typically via their own moduledataid attribute.

The tags themselves aren't configured on the moduledata instance at all - they're written at runtime by whichever module writes them. The tag filter module is the one that ships with SQL Relay for this purpose; see the tag filter module for how it's configured to write tags into an instance of this module, including its own tag and moduledataid attributes.

Custom modules may also be developed. For more information, please contact dev@firstworks.com.
