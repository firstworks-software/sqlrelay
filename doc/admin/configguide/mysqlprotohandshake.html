Handshake Protocol Version

Before a connecting client sends anything, the MySQL protocol module speaks first: it sends a handshake packet announcing which version of the wire protocol it supports. Clients read that packet to decide how to format everything that follows. Modern clients expect the modern handshake packet, known as protocol version 10. Only a client too old to have ever supported MySQL 4.1's authentication still expects the legacy handshake packet, protocol version 9.

The handshake attribute on the listener tag chooses which one the module sends. Setting it to anything other than 10 sends the legacy protocol version 9 handshake instead; 9 is the conventional value to use. Leaving it out, or setting it to 0 or to something that isn't a number, is the same as setting it to 10.

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="mysql">
		<listeners>
			<listener protocol="mysql" port="3306" handshake="9"/>
		</listeners>
		<connections>
			<connection string="user=mysqluser;password=mysqlpassword;db=mysqldb;host=mysqlhost"/>
		</connections>
	</instance>
</instances>

There is normally no reason to set this. It exists only for a client old enough to require the legacy handshake, and switching it on for a modern client doesn't degrade gracefully - the client simply fails to understand the packet.
