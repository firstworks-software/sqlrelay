sequence_nextval

The sequence_nextval module rewrites expressions that fetch the next value from a sequence, converting them from one database's syntax into another's. Different databases express this in different ways, so this is useful when running an application written for one database against another.

The module recognizes the following three syntaxes:

  • seqname.nextval - used by Oracle and DB2
  • nextval('seqname') - used by PostgreSQL
  • next value for seqname - used by SQL Server, Sybase, Firebird, and DB2

It rewrites any of these that it finds into the single target syntax selected by the style attribute. The sequence name, including any schema or owner prefix (eg. myschema.myseq), is preserved.

For example, with style=".nextval", a query like:

insert into mytable (id, name) values (nextval('myseq'), 'hello')

Would be translated to:

insert into mytable (id, name) values (myseq.nextval, 'hello')

An example configuration:

<?xml version="1.0"?>
<instances>
	...
	<instance id="example" ... >
		...
		<querytranslations>
			<querytranslation module="normalize"/>
			<querytranslation module="sequence_nextval" style=".nextval"/>
		</querytranslations>
		...
	</instance>
	...
</instances>

The following attribute is supported, in addition to the standard module, enabled, and debug attributes:

  • style - The target syntax to convert sequence-nextval expressions to. Options include:
    • .nextval - eg. myseq.nextval (Oracle, DB2)
    • nextval() - eg. nextval('myseq') (PostgreSQL)
    • next value for - eg. next value for myseq (SQL Server, Sybase, Firebird, DB2)
    • If omitted or set to an unrecognized value, queries are passed through untranslated.

Sequence references inside string literals are left alone.

The module assumes the query has already been normalized (single spaces between words, single dots in dotted names). As with the other modules, loading the normalize translation first helps it match reliably.
