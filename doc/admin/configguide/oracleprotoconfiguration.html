Basic Configuration

To enable SQL Relay to speak the Oracle protocol, add the appropriate listener tag:

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="oracle">
		<listeners>
			<listener protocol="oracle" port="1521"/>
		</listeners>
		<connections>
			<connection string="user=scott;password=tiger;oracle_home=/u01/app/oracle/product/12.1.0;oracle_sid=ora1"/>
		</connections>
	</instance>
</instances>

In this configuration:

  • The connection tag instructs the instance to log in to Oracle as user scott with password tiger, using the ora1 database in the Oracle installation under /u01/app/oracle/product/12.1.0.
  • The listener tag instructs SQL Relay to load the oracle protocol module, and listen on port 1521, which is the standard Oracle listener port.

The instance can be started using:

sqlr-start -id example

and accessed from the local machine using:

sqlplus scott/tiger@//localhost:1521
( NOTE: By default, the user and password used to access SQL Relay are the same as the user and password that SQL Relay is configured to use to access the database. That is, they are the values of the user and password parameters of the string attribute of the connection tag. )

By default, SQL Relay listens on all available network interfaces, and can be accessed remotely by hostname. For example, if the server running SQL Relay is named sqlrserver then it can be accessed from another system using:

sqlplus scott/tiger@//sqlrserver:1521

The instance can be stopped using:

sqlr-stop -id example

Since this instance speaks the Oracle client-server protocol, any client that wishes to use it must also speak the Oracle client-server protocol. This means that most software written using the Oracle API, or written using a database abstraction layer which loads a driver for Oracle can access this instance. However, it also means that SQL Relay's standard sqlrsh client program and client programs for other databases (eg. the mysql, and psql command line programs, MySQL Workbench, SQL Server Management Studio, etc.) cannot access this instance.
