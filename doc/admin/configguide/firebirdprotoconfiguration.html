Basic Configuration

To enable SQL Relay to speak the Firebird protocol, add the appropriate listener tag:

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="firebird" maxcursors="64">
		<listeners>
			<listener protocol="firebird" port="3050"/>
		</listeners>
		<connections>
			<connection string="user=firebirduser;password=firebirdpassword;db=firebirdhost:/opt/firebird/firebirddb.gdb"/>
		</connections>
	</instance>
</instances>

In this configuration:

  • The listener tag instructs SQL Relay to load the firebird protocol module, and listen on port 3050, which is the standard Firebird port.
  • The connection tag instructs the instance to log in to the /opt/firebird/firebirddb.gdb database on the Firebird server firebirdhost as user firebirduser with password firebirdpassword.
  • maxcursors is set to 64. The isql client uses a bunch of separate cursors when executing SHOW commands, and holds them until it disconnects.

The instance can be started using:

sqlr-start -id example

and accessed from the local machine using:

isql -user firebirduser -password firebirdpassword localhost/3050:/opt/firebird/firebirddb.gdb
( NOTE: By default, the user and password used to access SQL Relay are the same as the user and password that SQL Relay is configured to use to access the database. That is, they are the values of the user and password parameters of the string attribute of the connection tag. )

By default, SQL Relay listens on all available network interfaces, and can be accessed remotely by hostname. For example, if the server running SQL Relay is named sqlrserver then it can be accessed from another system using:

isql -user firebirduser -password firebirdpassword sqlrserver/3050:/opt/firebird/firebirddb.gdb

The instance can be stopped using:

sqlr-stop -id example
