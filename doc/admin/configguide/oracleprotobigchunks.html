Big Chunks

Oracle clients and servers split long values into pieces, and there are two ways of encoding each piece's length: an older one, limited to 255 bytes per piece, and a newer "big chunk" one. At login, the Oracle protocol module tells the client that it supports big chunks, and then uses them only if the client says it does too. The bigchunkclr option overrides this:

  • auto - use big chunks only with clients that say they support them. This is the default.
  • off - never use big chunks, or tell clients they are supported. This is for clients that say they support big chunks, but don't (eg. go-ora v1).
  • on - use big chunks with every client new enough to support them, even if the client doesn't say so.

Any other value is the same as auto.

<?xml version="1.0"?>
<instances>
	<instance id="example" dbase="oracle">
		<listeners>
			<listener protocol="oracle" port="1521" bigchunkclr="off"/>
		</listeners>
		<connections>
			<connection string="user=scott;password=tiger;oracle_home=/u01/app/oracle/product/12.1.0;oracle_sid=ora1"/>
		</connections>
	</instance>
</instances>
