Persistent Database Connection Pooling

A persistent database connection pool maintains a set of already-logged-in database connections, and hands them out to applications, on-demand. Connection pools provide several advantages over direct database connections, but primarily the persistent connections improve application performance and responsiveness, and the limited number of connections throttle requests to limit database load.

Application Performance and Responsiveness

Logging in to most databases takes a noticable amount of time...

Web-based applications, and other transient apps, which connect, log in, query, log out, and disconnect to deliver each bit of content, often spend more time logging in than running queries. Page loads feel slow, and overall throughput, in queries-per-second, is generally low unless many queries are run per connection.

Connecting to a pool, and being handed an already-logged in database connection is substantially faster than logging into the database directly.

Overall throughput (queries-per-second) is maximized, and doesn't depend nearly as much on the number of queries that are run per connection.
